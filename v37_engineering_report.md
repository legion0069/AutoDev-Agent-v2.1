# AutoDev Version 3.7 Engineering Report

## Release scope

Version 3.7 adds deterministic, explainable engineering decision support while
preserving the existing task, organizational decision, scientific hypothesis,
and reflection interfaces. It does not expose hidden chain-of-thought. Its
public outputs are structured summaries, scored options, explicit evidence,
dependency findings, and outcome metrics.

## Architecture and public surface

| Module | Public surface | Responsibility |
| :--- | :--- | :--- |
| `core/reasoning_engine.py` | `ReasoningEngine` | Deterministic task summary, cost estimate, risk, confidence, benefit, and feasibility. |
| `core/decision_engine.py` | `DecisionEngine.rank_options()`, `.score_options()`, `.choose_best()` | Weighted strategy ranking added alongside the existing organizational proposal/vote APIs. |
| `core/hypothesis_engine.py` | `HypothesisEngine.generate()`, `.rank()`, `.validate()`, `.learn()` | Stable issue-hypothesis IDs and explicit evidence tracking; existing scientific hypothesis APIs remain available. |
| `core/planning_revision.py` | `PlanningRevisionEngine`, `PlanningRevision`, `PlanReview` | Dependency checks, deterministic repair of missing/self/cyclic edges, and conflict-safe parallel opportunity groups. |
| `core/knowledge_reasoner.py` | `KnowledgeReasoner` | Explainable lexical retrieval over supplied records and task context. |
| `core/explainability.py` | `ExplainabilityEngine` | Sanitized decision, plan, task, and report explanations. |
| `core/reasoning_cache.py` | `ReasoningCache` | Versioned content-addressed JSON persistence, atomic writes, corruption/version recovery, and cache statistics. |
| `benchmark_v37_reasoning.py` | `run_benchmarks()` | Reproducible cold/warm microbenchmarks and JSON history/report output. |

All strategy scores use fixed weights and sorted tie-breakers. Cache keys are
canonical JSON SHA-256 digests. Cache entries carry a version and key; malformed
or incompatible entries are removed and treated as misses. Writes use a
temporary file and atomic replacement. Caches are disposable and kept below
`memory/cache/reasoning/`.

## Orchestration and learning integration

Before task execution, the orchestrator reviews and safely repairs a generated
plan, attaches its dependency-safe parallel groups and public explanation,
builds structured reasoning summaries, and ranks strategy options. For each
task it adds issue hypotheses, relevant prior learning, and a sanitized task
explanation to the existing context. The task execution loop remains sequential:
parallel groups describe independent work but do not introduce concurrent task
execution or change task ordering.

After task completion, the existing learning lifecycle now stores structured
reflection dimensions for planning reliability, test adequacy, output quality,
prompt efficiency, reliability, execution duration, affected-file count, and
improvement priorities. Existing reflection reports and learning-event results
remain available; the return mapping only gains an additional
`structured_reflection` entry.

## Measured benchmark results

Generated by `python benchmark_v37_reasoning.py` on Python 3.14.2/Linux. The run
used 30 warm iterations, a 100-task dependency chain, 100 knowledge records, and
two strategy options. Cold and warm calls used the same input; cold measurements
used a new cache directory and warm measurements reused a populated cache.

| Measurement | Cold median (s) | Warm / repeated median (s) | Observed change |
| :--- | ---: | ---: | ---: |
| Structured reasoning | 0.001260 | 0.000208 | 83.48% lower latency |
| Strategy ranking | 0.001220 | 0.000243 | 80.07% lower latency |
| Issue hypothesis generation | 0.001415 | 0.000265 | 81.29% lower latency |
| Knowledge retrieval | 0.012790 | 0.003281 | 74.35% lower latency |
| Planning revision, 100 tasks | — | 0.075904 | Uncached operation |
| Explanation formatting, 100 tasks | — | 0.002199 | Uncached operation |

The aggregate warm-cache hit ratio across reasoning, strategy, hypothesis, and
knowledge caches was **96.77%** (120 hits, 4 initial misses). Peak traced Python
allocations were 145,225 bytes for cold reasoning and 134,567 bytes for repeated
warm reasoning. The raw per-iteration measurements and additional allocation
figures are in
[`memory/benchmarks/v37_reasoning_benchmark_results.json`](./memory/benchmarks/v37_reasoning_benchmark_results.json).

These are microbenchmark results for the stated workload. They do not measure
end-to-end orchestration duration, process RSS, repository-wide speedup, or
performance relative to Version 3.6.1. Cold timing includes object/cache setup;
tracemalloc reports Python allocations rather than resident memory. No broader
performance claim is made.
